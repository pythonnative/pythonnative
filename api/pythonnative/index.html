    Package overview¶

    PythonNative re-exports a small public surface from pythonnative/__init__.py. Most user code only ever touches the names in this overview. Opt-in device features live in capability subpackages, and deeper internals (reconciler, native_views, hosts) are documented for contributors and integrators.

    Entry point¶

    Your app module defines a top-level component named App:

    import pythonnative as pn


@pn.component
def HomeScreen() -> pn.Node:
    return pn.Text("Hello from PythonNative")


Root = pn.StackNavigator(HomeScreen)


@pn.component
def App() -> pn.Node:
    return pn.NavigationContainer(Root)

    The bundled Android ScreenFragment and iOS ViewController load your app by module path ("app.main") and look up the module's top-level App attribute. There is no registration step or imperative bootstrap call. If you need to expose a differently-named root component, configure the templates to load an explicit dotted path like "app.main.RootScreen" instead.

    PythonNative: declarative native UI for Android and iOS.

    PythonNative is a cross-platform toolkit that turns Python @component functions into real, native Android and iOS views. The component model is React-like (function components plus hooks). Python owns the logical component tree and reconciliation on a dedicated asyncio application thread. Versioned commits go to a shared C++ renderer core, which every target links. The core validates each commit against the native contracts, lays it out with Yoga off the UI thread, flattens layout-only views, and runs animation graphs. Swift PythonNativeKit on iOS and the Kotlin pythonnative module on Android mount the result: they own widgets, text drawing, input, and the frame clock on the platform UI thread. The browser preview runs the same core as WebAssembly and mounts DOM widgets.

    Key building blocks:

    • Element factories (Text, Button, Column, etc.) return immutable Element descriptors.
    • Hooks (use_state, use_effect, use_reducer, etc.) manage state, side effects, and context inside @component functions.
    • Navigation: screens are components whose parameters are their route params, listed in module-level StackNavigator, TabNavigator, or DrawerNavigator values and rendered by NavigationContainer. nav.push(ItemScreen(id=42)) is checked by the type checker.
    • Styling uses a style dict per element (or a list of dicts), typed by the Style TypedDict. StyleSheet namespaces group named styles, and one Theme styles the app and its navigators.
    • State lives in hooks for a component and in a typed Store for the app.
    • Motion (RFC 0009): worklet functions run on the UI thread inside the renderer core. They read and write SharedValues, which use_animated_style turns into styles and with_timing / with_spring / with_decay animate. Event props and gesture callbacks take worklets, and views take entering=, exiting=, layout=, and shared_tag=.
    • Gestures attach to any view via the gestures= prop using descriptors from pythonnative.gestures (Tap, LongPress, Pan, Swipe, Pinch, Rotation).
    • Custom native components can be authored with the pythonnative.sdk package: define a typed Props dataclass and declare the component with define_component, which returns its element factory (or expose it from a PyPI package via the pythonnative.handlers entry-point group).
    • Capabilities are opt-in device features, one subpackage each: pythonnative.audio, background, biometrics, camera, location, maps, notifications, pickers, purchases, push, sensors, and video. They aren't re-exported here. List one in [plugins].use in pythonnative.toml to compile it into the app, then import it by name: from pythonnative.camera import CameraView. Calling one that isn't in the build raises NativeModuleError with the code plugin_not_enabled.
    • Failures in a release build reach set_error_handler, and a render error no boundary catches shows the screen set with set_error_fallback.
    Example 
    import pythonnative as pn

@pn.component
def App() -> pn.Node:
    count, set_count = pn.use_state(0)
    return pn.Column(
        pn.Text(f"Count: {count}", style=pn.style(font_size=24)),
        pn.Button("+", on_press=lambda: set_count(count + 1)),
        style=pn.style(gap=12),
    )

    Property reference¶

    All visual and layout properties pass through the style dict (or a list of dicts). The full per-component property catalogue lives in Component properties.
