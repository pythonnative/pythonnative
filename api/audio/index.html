    Audio¶

    Sound plays audio, Recorder records it, and Audio.set_mode sets how the app's audio relates to the device and other apps. Enable it with use = ["audio"] under [plugins]. See the Audio guide.

    Audio playback and recording.

    Enable it in pythonnative.toml. Playback needs nothing else; recording also needs a microphone usage string:

    [plugins]
use = ["audio"]

[permissions]
microphone = "Record voice notes."
    Example 
    from pythonnative.audio import Audio, Recorder, Sound

async def chime() -> None:
    Audio.set_mode(category="playback")
    sound = await Sound.load("https://example.com/chime.mp3")
    sound.on_end(sound.unload)
    sound.play()

async def voice_note() -> None:
    recorder = await Recorder.start()
    await asyncio.sleep(3)
    recording = await recorder.stop()
    async with await Sound.load(recording.path) as sound:
        sound.play()
        await asyncio.sleep(recording.duration)

    Sound ¶

    Sound(id: int, *, looping: bool = False)

    One loaded sound. Create it with Sound.load.

    After a sound plays to its end, it rewinds to the start, so play() plays it again. Playback pauses when the app goes to the background.

    Using it as an async context manager unloads it on exit:

    async with await Sound.load(asset) as sound:
    sound.play()

    Audio ¶

    App-wide audio behavior.

    Methods:

    Name Description
    set_mode

    Set how the app's audio relates to the device and to other apps.

    set_mode staticmethod ¶

    set_mode(
    *,
    category: AudioCategory = "playback",
    mix_with_others: bool = False,
    duck_others: bool = False,
    default_to_speaker: bool = False,
    allow_bluetooth: bool = False
) -> None

    Set how the app's audio relates to the device and to other apps.

    This is mainly iOS's AVAudioSession. Each call replaces the whole mode. Without a call, iOS uses solo_ambient, which the silent switch mutes; call this with category="playback" for sound the user asked to hear. A running Recorder switches to play_and_record and restores this mode when it stops.

    Android has no categories, so category, default_to_speaker, and allow_bluetooth have no effect there. mix_with_others and duck_others control whether a Sound takes audio focus, which pauses or lowers other apps. In the browser preview this does nothing.

    Parameters:

    Name Type Description Default
    category AudioCategory

    The AVAudioSession category.

    		 'playback'
    mix_with_others bool

    Play alongside other apps' audio.

    		 False
    duck_others bool

    Play over other apps' audio, lowering it.

    		 False
    default_to_speaker bool

    With play_and_record, use the speaker rather than the receiver.

    		 False
    allow_bluetooth bool

    With record or play_and_record, offer Bluetooth headsets as inputs.

    		 False

    Raises:

    Type Description
    NativeModuleError

    With the code invalid_mode when iOS rejects the combination.
